# Video2Knowledge UI 优化方案

> 版本：V2.0 / Production To-C Edition  
> 日期：2026-08-01  
> 状态：替代此前的毛玻璃视觉方案  
> 核心方向：克制、清晰、可信、具有编辑气质的消费级内容产品

---

## 0. 结论

新版本不再追求“看起来像 AI 产品”，而是追求：

> 即使去掉渐变、动效和 AI 文案，界面仍然因为排版、比例、层级和细节而显得高级。

视觉方向从“玻璃拟态 AI 工作台”调整为 **Editorial Utility / 编辑型生产力工具**：

- 温和的中性色背景。
- 清晰、有力度的黑白排版。
- 少量克制的钴蓝色作为功能强调。
- 大面积实体表面，不使用毛玻璃。
- 不依赖光晕、渐变、胶囊和漂浮效果制造高级感。
- 动效只解释交互，不承担视觉装饰。
- AI 能力隐藏在流程中，不在视觉上反复强调。

最终产品应像一个成熟的内容编辑工具，而不是一个套用了 AI 设计模板的后台页面。

---

## 1. 为什么上一版不成立

### 1.1 视觉符号过度 AI 化

上一版集中使用了以下已经高度模板化的视觉符号：

- 蓝紫径向渐变。
- 毛玻璃面板。
- 发光边缘和环境光斑。
- “AI 工作台”胶囊标签。
- 渐变 Logo。
- 光扫、呼吸光和悬浮卡片。
- 大圆角和大量圆形 Chip。

这些元素单独使用没有问题，但同时出现会快速产生“AI 生成页面”的观感。它们表达的是技术感，而不是产品品质。

### 1.2 装饰超过内容

Video2Knowledge 的价值是将视频整理为结构良好的技术内容。用户真正关心的是：

1. 素材是否成功进入系统。
2. 当前处理到哪一步。
3. 生成结果是否专业、可信、可编辑。
4. 内容能否方便地管理和导出。

界面应该强化这些信息，而不是让用户先看到视觉风格。

### 1.3 高级感的来源判断错误

生产级 To C 产品的高级感通常来自：

- 信息删减是否准确。
- 字体、字号、行高和字重是否成熟。
- 留白是否服务于阅读节奏。
- 交互是否自然、可预测。
- 组件是否稳定、一致。
- 空状态、错误状态和加载状态是否完整。
- 文案是否像人说话。

而不是来自模糊半径、渐变数量或动画强度。

## 2. 产品定位

### 2.1 产品角色

Video2Knowledge 不是“AI 模型控制台”，也不是“视频处理后台”。

它是一个面向个人创作者、技术作者、知识博主和研究者的内容生产工具：

> 输入一段视频或音频，得到一篇结构完整、可以继续编辑和发布的文章。

### 2.2 用户对产品的心理预期

用户上传的可能是未公开课程、访谈、播客或工作资料。因此产品必须传递：

- 稳定。
- 安静。
- 可信。
- 内容不会失控。
- 操作结果可预期。
- 长时间使用不会疲劳。

### 2.3 设计关键词

- Editorial 编辑感
- Precise 精确
- Calm 安静
- Trustworthy 可信
- Contemporary 当代
- Human 人性化

### 2.4 明确排除的方向

- 不做赛博科技感。
- 不做 Web3 风格。
- 不做玻璃拟态。
- 不做大面积蓝紫渐变。
- 不做“未来已来”式 AI 文案。
- 不用装饰性粒子、光斑和无限循环动画。
- 不模仿传统企业管理后台。

## 3. 核心体验目标

### 3.1 首次使用

- 用户进入页面 3 秒内知道这是做什么的。
- 5 秒内找到上传入口。
- 不理解 ASR、Prompt、Preset 也可以完成第一次任务。
- 第一次使用不要求用户配置模型。

### 3.2 日常使用

- 从进入页面到开始上传不超过两次操作。
- 最近任务无需进入二级页面即可继续查看。
- 处理状态清楚，但不过度占据注意力。
- 文章结果以阅读和编辑为主，而不是以“模型输出”为主。

### 3.3 专业感

- 用户截取任意主要页面，都不应出现明显的模板化 AI 视觉符号。
- 即使将页面转为灰度，信息层级仍然清楚。
- 关闭全部动效后，产品仍然显得完整和高级。

## 4. 品牌视觉

### 4.1 品牌表达

产品名称建议在界面中统一使用 `Video2Knowledge`。

避免同时出现 Video2TechBlog、Video2Knowledge、AI 技术内容工作台等多个名称。

#### Logo 建议

- 使用纯文字标识或简单的单色几何符号。
- 不使用蓝紫渐变方块。
- 图形可以从“播放标记”和“文本段落”抽象组合，但保持单色。
- 小尺寸下优先保证识别，不追求复杂含义。

#### 品牌文案

主文案：

> 把视频整理成一篇好文章

辅助文案：

> 上传视频、音频或链接，获得结构清晰、可以继续编辑的技术内容。

不使用：

- AI 技术内容工作台。
- 一次上传，释放知识生产力。
- 让 AI 重塑内容未来。
- 智能驱动、灵感无限。

这些文案信息密度低，也容易增加廉价的 AI 营销感。

## 5. 视觉设计系统

### 5.1 色彩

整体使用温和、中性的纸张与墨色体系，钴蓝只承担交互强调。

#### 页面色

| Token | 色值 | 用途 |
|---|---:|---|
| `--page` | `#F5F5F3` | 页面背景，略带暖色 |
| `--surface` | `#FFFFFF` | 主内容表面 |
| `--surface-subtle` | `#FAFAF8` | 次级内容、表头、Hover |
| `--surface-sunken` | `#EFEFED` | 输入型或嵌入型区域 |

#### 文字色

| Token | 色值 | 用途 |
|---|---:|---|
| `--ink` | `#171717` | 标题、按钮、正文主色 |
| `--ink-secondary` | `#62625F` | 描述与次要信息 |
| `--ink-tertiary` | `#94948E` | 时间、占位符、弱提示 |
| `--ink-disabled` | `#B8B8B2` | 禁用状态 |

#### 边界色

| Token | 色值 | 用途 |
|---|---:|---|
| `--line` | `#E7E7E3` | 普通分隔线 |
| `--line-strong` | `#D8D8D3` | 输入框和强调边界 |

#### 功能强调色

| Token | 色值 | 用途 |
|---|---:|---|
| `--accent` | `#335CFF` | 链接、焦点、处理进度 |
| `--accent-hover` | `#244BE3` | Hover |
| `--accent-soft` | `#EDF1FF` | 选中背景 |

#### 状态色

| 状态 | 前景 | 背景 |
|---|---:|---:|
| 成功 | `#177A55` | `#ECF6F1` |
| 警告 | `#956312` | `#FBF4E7` |
| 错误 | `#B43C4F` | `#FBECEF` |

#### 色彩约束

- 页面不使用装饰性渐变。
- 主按钮优先使用接近黑色的 `--ink`，而不是品牌蓝。
- 品牌蓝用于焦点、链接、进度和少量选中状态。
- 单个视图内避免同时出现超过三种状态色。
- 不使用紫色表达“AI”。

### 5.2 字体与排版

#### 字体栈

```css
font-family:
  Inter,
  "SF Pro Text",
  "PingFang SC",
  "Microsoft YaHei",
  system-ui,
  sans-serif;
```

不依赖花哨展示字体。中文环境下，正确的字号、字重和行高比字体品牌更重要。

#### 字体层级

| 类型 | 字号/行高 | 字重 | 用途 |
|---|---|---:|---|
| Display | `42/50` | 650 | 桌面端首页主标题 |
| Page title | `28/36` | 650 | 页面标题 |
| Section title | `18/26` | 600 | 区块标题 |
| Card title | `15/22` | 600 | 任务名称 |
| Body | `15/25` | 400 | 正文与说明 |
| UI | `14/20` | 500 | 按钮、表单、导航 |
| Caption | `12/18` | 400 | 时间、状态、元数据 |

#### 排版规则

- 主标题避免超过两行。
- 中文正文行高不低于 1.65。
- 标题字重最高使用 650，不大量使用 700/800。
- 辅助文字不使用过浅灰色，保证真实屏幕上的可读性。
- 不用英文全大写 Eyebrow 作为装饰。
- 不使用过度负字距。

### 5.3 圆角

| 组件 | 圆角 |
|---|---:|
| 小按钮、Chip | `8px` |
| 输入框、普通按钮 | `10px` |
| 普通卡片 | `12px` |
| 主上传面板 | `16px` |
| Modal / Drawer | `16px` |

禁止所有容器统一使用 20–28px 大圆角。大圆角会让专业工具显得像营销落地页。

### 5.4 阴影与材质

#### 普通页面

主要依靠背景、边界和留白建立层级，不使用阴影。

#### 主上传面板

```css
border: 1px solid #e2e2de;
background: #fff;
box-shadow:
  0 1px 2px rgba(23, 23, 23, 0.03),
  0 12px 36px rgba(23, 23, 23, 0.05);
```

#### 浮层

```css
box-shadow:
  0 16px 48px rgba(23, 23, 23, 0.12),
  0 2px 8px rgba(23, 23, 23, 0.06);
```

不使用：

- 发光阴影。
- 彩色阴影。
- 内发光。
- 玻璃折射边缘。

### 5.5 间距

采用 8px 主栅格，4px 用于微调。

```text
4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 / 80
```

- 页面最大宽度：1200px。
- 桌面端页面边距：32px。
- 移动端页面边距：16px。
- 页面标题与主体：32px。
- 大区块之间：48–64px。
- 卡片内部：20–24px。

## 6. 全局框架

### 6.1 顶部导航

```text
┌─────────────────────────────────────────────────────────────┐
│ Video2Knowledge     新建内容   内容库             设置     │
└─────────────────────────────────────────────────────────────┘
```

规格：

- 高度 64px。
- 实体页面色背景，不透明。
- 底部使用 1px 分隔线。
- 左侧为单色 Logo 和产品名。
- 导航使用普通文字，不放在胶囊容器内。
- 当前导航通过深色文字和细下划线表达。
- 设置使用统一线性图标。
- 不显示“AI 技术内容工作台”副标题。

### 6.2 图标系统

- 全站使用同一套 1.75–2px 线性图标。
- 统一尺寸：16、18、20、24。
- 不混用 Emoji、字符图标、实心图标和不同 SVG 风格。
- 图标按钮必须有 Tooltip 和可访问名称。
- 空状态可以使用简单单色插图，但不能使用 AI 机器人、魔法棒或星光图形。

### 6.3 页面宽度

- 上传首页：最大 1200px。
- 内容库：最大 1200px。
- 处理工作区：最大 1280px。
- 文章正文：最大 760px。
- 文章详情含大纲：主内容 760px，大纲 220px。

## 7. 新建内容页

### 7.1 页面布局

桌面端采用非对称双栏布局，避免所有内容居中堆叠形成营销模板感。

```text
┌────────────────────────────── 页面 1200px ──────────────────────────────┐
│                                                                          │
│  把视频整理成一篇好文章          ┌───────────────────────────────────┐  │
│                                  │                                   │  │
│  上传视频、音频或链接，获得      │  拖入视频或音频                   │  │
│  结构清晰、可以继续编辑的内容。  │  或从电脑选择文件                 │  │
│                                  │                                   │  │
│  · 自动整理章节                  │  支持 MP4、MOV、MP3、WAV          │  │
│  · 提炼知识结构                  │                                   │  │
│  · 生成可编辑文章                │  [选择文件]                       │  │
│                                  ├───────────────────────────────────┤  │
│                                  │ 本地文件  媒体链接   更多设置     │  │
│                                  └───────────────────────────────────┘  │
│                                                                          │
│  最近内容                                                    查看全部   │
│  ─────────────────────────────────────────────────────────────────────  │
│  标题                              状态              更新时间           │
└──────────────────────────────────────────────────────────────────────────┘
```

#### 左侧价值区

- 占 5 栏。
- 标题最多两行。
- 不放置 AI Badge、英文 Eyebrow 或视觉光斑。
- 三个能力点使用普通文本和小型勾选图标。
- 在 1024px 以下合并为单列。

#### 右侧上传区

- 占 7 栏。
- 使用实体白色面板。
- 面板是首屏唯一明显阴影容器。
- 拖拽区域用背景色区别，不用虚线大圆角玻璃框。
- 文件与链接通过底部文字 Tab 切换。
- 主按钮使用深色实体按钮。

### 7.2 上传交互

#### 默认状态

- 标题：`拖入视频或音频`
- 辅助：`也可以从电脑中选择文件`
- 按钮：`选择文件`
- 支持格式放在最底部，降低视觉权重。

#### Drag Over

- 背景从 `#FAFAF8` 变为 `#F3F5FF`。
- 边框变为钴蓝。
- 上传图标上移 2px。
- 不缩放整个面板。
- 不出现发光效果。

#### 上传中

- 文件名始终可见。
- 展示细进度条和百分比。
- 文案：`正在上传，42%`
- 支持取消上传时提供弱操作。
- 不使用 Shimmer 渐变。

#### 上传完成

- 展示文件名、文件类型和大小。
- 状态文字：`文件已就绪`
- 主按钮切换为 `开始整理`
- 成功状态不占满整个上传区域。

### 7.3 高级设置

默认不显示 ASR、Prompt、Preset 等技术名词。

上传面板底部仅保留：

```text
输出：技术文章    语言：中文    更多设置
```

点击“更多设置”后在右侧打开 Drawer：

- 输出类型。
- 识别语言。
- 转录方式。
- 文章预设。
- 高级提示词入口。

对普通用户使用业务语言：

| 技术词 | 用户界面文案 |
|---|---|
| ASR Provider | 转录方式 |
| Preset | 文章风格 |
| Prompt | 生成规则 |
| Regenerate | 重新生成文章 |
| Stage | 处理步骤 |

### 7.4 最近内容

- 不使用三张悬浮卡片。
- 使用简洁的三行内容列表。
- 每行包含来源图标、标题、状态和更新时间。
- 整行点击进入详情。
- 没有内容时整个区域隐藏，不重复展示空状态。

## 8. 处理页

### 8.1 页面目标

用户只需要知道：

1. 当前正在做什么。
2. 是否正常运行。
3. 已经产生了什么内容。
4. 是否可以离开页面。

### 8.2 桌面布局

```text
┌────────────────────────────────────────────────────────────────────────┐
│ React Server Components 教程                         03:42   [停止]    │
│ 正在转录 · 38%                                                        │
├──────────────────┬──────────────────────────────────────┬──────────────┤
│ 处理步骤          │ 实时内容                             │ 任务信息     │
│                  │                                      │              │
│ ✓ 准备音频        │ 这里显示已完成的转录段落、章节或      │ 文件         │
│ ● 语音转录        │ 文章内容。                           │ 语言         │
│ ○ 整理章节        │                                      │ 转录方式     │
│ ○ 提炼知识        │ 不重复显示五张步骤卡。               │ 创建时间     │
│ ○ 生成文章        │                                      │              │
└──────────────────┴──────────────────────────────────────┴──────────────┘
```

#### 顶部任务栏

- 标题、当前状态、总体进度、耗时和停止操作。
- 使用 4px 细进度条贯穿内容区顶部。
- 百分比使用等宽数字。
- 停止操作为文字按钮，不使用大面积红色。

#### 左侧步骤

- 宽度 200–220px。
- 当前步骤使用左侧 2px 强调线和深色文字。
- 已完成步骤使用勾选图标。
- 未开始步骤使用中性灰。
- 不使用呼吸光、环形发光和旋转图标。
- 只有在无法确定进度时使用小型 Spinner。

#### 中间实时内容

- 宽度优先，白色实体背景。
- 转录内容按段落进入。
- 用户滚动离开底部后停止自动跟随。
- 底部出现 `回到最新` 按钮。
- 内容区域不使用等宽字体，时间戳可以使用等宽数字。

#### 右侧任务信息

- 宽度 220px。
- 只展示稳定元数据。
- 小屏幕下折叠为顶部信息按钮。

### 8.3 完成状态

完成时不播放庆祝动画。

变化顺序：

1. 进度条到达 100%。
2. 状态文案改为 `处理完成`。
3. 主操作出现：`查看文章`。
4. 次操作：`查看处理详情`。

使用一次 160ms 淡入即可。

## 9. 内容库

### 9.1 页面结构

```text
内容库                                                   [新建内容]
管理所有视频、音频和生成文章

[搜索内容……                              ] [状态] [来源] [排序]

标题                               来源      状态       更新时间        ···
──────────────────────────────────────────────────────────────────────────
React Server Components 教程       视频      已完成     今天 14:32      ···
AI Agent 播客访谈                   音频      处理中     今天 13:08      ···
```

### 9.2 列表而非卡片

- 桌面端使用内容列表或轻表格。
- 不为每条内容增加圆角边框卡片。
- 行高 72px。
- 行之间使用细分隔线。
- Hover 只改变背景色。
- 整行点击进入详情。
- 操作集中在 `···` 菜单。
- 删除不直接展示在列表上。

### 9.3 状态

状态采用“小圆点 + 文本”，尽量不使用大面积标签：

```text
● 已完成
● 处理中
● 失败
○ 等待开始
```

状态颜色只作用于圆点，文字保持中性色，降低列表噪音。

### 9.4 搜索和筛选

- 搜索输入后 300ms 自动查询。
- 筛选项使用普通 Select 或 Popover，不使用大量胶囊 Chip。
- 筛选结果应显示数量。
- 刷新操作放进更多菜单或使用低权重图标。

### 9.5 空状态

```text
还没有内容
上传一段视频，开始创建第一篇文章。

[新建内容]
```

空状态只使用一个简单单色图形，不出现机器人、魔法棒或星光。

## 10. 内容详情与文章阅读

### 10.1 顶部信息

- 返回内容库。
- 内容标题。
- 来源、时长、创建时间等元信息。
- 右侧主操作：`导出`。
- 次级操作进入 `···` 菜单。

不在标题旁同时摆放重新处理、删除、导出等多个彩色按钮。

### 10.2 内容导航

```text
视频   音频   转录   章节   知识   文章
```

- 使用文字 Tab 和底部细线。
- 当前 Tab 使用深色文字。
- 指示线使用钴蓝。
- Tabs 吸附在内容区顶部。
- 移动端支持水平滚动。

### 10.3 文章模式

文章是产品最重要的结果，应像成熟的阅读器和编辑器。

#### 阅读宽度

- 正文最大宽度 760px。
- 页面中央偏左，不机械绝对居中。
- 大屏幕右侧显示文章大纲。

#### 正文规格

- 正文 16px，行高 1.8。
- 段落间距 16–20px。
- H1 为 32px。
- H2 为 24px，上间距 48px。
- H3 为 19px，上间距 32px。
- 列表项间距 8px。
- 代码块使用深墨色实体背景。
- 引用块使用左侧 2px 边界，不使用彩色大背景。

#### 操作栏

- 导出。
- 复制 Markdown。
- 重新生成文章。
- 更多操作。

避免按钮全都常驻。主操作保留，其他收入菜单。

## 11. 设置与弹层

### 11.1 Drawer

文章风格、转录方式和生成规则使用右侧 Drawer。

- 宽度 520–640px。
- 实体白色背景。
- 不透明。
- 左侧使用普通遮罩，不使用背景模糊。
- 标题固定，内容滚动，操作栏固定。
- 打开时锁定焦点。
- Esc 关闭。

### 11.2 Modal

只用于需要用户立即决策的操作：

- 删除确认。
- 停止任务确认。
- 覆盖已有文章。

删除确认文案必须包含具体内容标题。

### 11.3 Toast

- 右下角显示。
- 白色实体卡片。
- 左侧状态图标。
- 普通提示 3 秒消失。
- 错误提示保留 6 秒，并提供重试。
- 不使用彩色大背景。

## 12. 组件规范

### 12.1 按钮

#### Primary

- 深墨色背景 `#171717`。
- 白色文字。
- 高度 42px。
- 圆角 10px。
- 每个页面状态最多一个 Primary。

#### Secondary

- 白色背景。
- 1px 中性边界。
- 深色文字。

#### Text

- 无背景和边界。
- 用于返回、取消、更多设置等低权重操作。

#### Danger

- 默认使用红色文字。
- 只有最终删除确认使用红色实体背景。

#### 禁用状态

- 不只降低透明度。
- 同时改变光标与文字颜色。
- 必要时说明禁用原因。

### 12.2 输入框

- 高度 42–44px。
- 白色背景。
- 默认边界 `#D8D8D3`。
- Focus 使用 1px 钴蓝边界和 2px 浅蓝 Ring。
- 错误状态包含图标和文字。
- Placeholder 对比度不能过低。

### 12.3 卡片

卡片仅用于真正需要形成内容组的场景：

- 上传主面板。
- 空状态。
- 统计摘要。
- 独立设置模块。

列表项不默认卡片化。

### 12.4 标签

- 标签用于分类，不用于所有元信息。
- 状态优先使用圆点 + 文本。
- 标签圆角 6–8px，不统一做成胶囊。
- 一行中最多出现两个标签。

### 12.5 菜单

- 次级操作统一放入 `···` 菜单。
- 危险操作与普通操作之间增加分隔线。
- 菜单项使用动词开头：`重新处理`、`导出内容`、`删除内容`。

## 13. 动效规范

### 13.1 动效定位

动效不是视觉风格，而是交互反馈。

产品中不应存在持续吸引注意力的装饰动画。

### 13.2 时间与缓动

```css
--duration-instant: 100ms;
--duration-fast: 160ms;
--duration-normal: 220ms;
--duration-panel: 260ms;

--ease-standard: cubic-bezier(0.2, 0, 0, 1);
--ease-enter: cubic-bezier(0.16, 1, 0.3, 1);
--ease-exit: cubic-bezier(0.4, 0, 1, 1);
```

### 13.3 允许使用的动效

| 场景 | 属性 | 距离/变化 | 时长 |
|---|---|---:|---:|
| 按钮 Hover | 背景色 | 轻微变深 | 120ms |
| 行 Hover | 背景色 | `#FFF → #FAFAF8` | 120ms |
| Popover 出现 | opacity + translateY | 4px | 160ms |
| Drawer 进入 | opacity + translateX | 16px | 240ms |
| Modal 进入 | opacity + scale | 0.99 → 1 | 180ms |
| 新段落进入 | opacity + translateY | 3px | 180ms |
| 进度更新 | scaleX | 按真实进度 | 220ms |

### 13.4 禁止使用的动效

- 卡片光扫。
- 发光呼吸环。
- 页面环境光移动。
- 循环漂浮。
- 3D 倾斜。
- Hover 大幅缩放。
- 液态渐变。
- 彩色 Shimmer。
- 逐字跳动。
- 完成时撒花或粒子动画。

### 13.5 加载状态

- 优先使用稳定骨架布局。
- 骨架对比度低于 8%。
- 只运行一次缓慢明暗过渡，或使用静态骨架。
- 小范围未知进度可以使用 14–16px Spinner。
- 不让整个页面同时闪烁。

### 13.6 Reduced Motion

所有非必要动效必须支持 `prefers-reduced-motion`，关闭后不影响层级和操作理解。

## 14. 文案规范

### 14.1 原则

- 使用用户语言，不使用工程术语。
- 说清楚当前发生什么以及用户下一步能做什么。
- 避免拟人化和夸张承诺。
- 不在每个页面重复强调 AI。

### 14.2 文案替换

| 当前或不推荐文案 | 推荐文案 |
|---|---|
| 新建任务 | 新建内容 |
| 上传内容 | 添加素材 |
| 开始生成 | 开始整理 |
| 产物 | 文章 |
| 资产管理 | 内容库 |
| 提示词预设 | 文章风格 |
| ASR | 转录方式 |
| 知识提取 | 提炼知识 |
| 重新生成产物 | 重新生成文章 |
| 上传成功 | 文件已就绪 |
| 正在处理 | 正在整理内容 |

### 14.3 错误文案

错误信息需要包含：

1. 发生了什么。
2. 可能的原因。
3. 用户下一步可以做什么。

示例：

> 无法读取这个链接。该平台可能需要登录，你可以下载视频后改为上传本地文件。

避免：

> 处理失败，请重试。

- 正文和背景对比度达到 WCAG AA。

## 18. 验收标准

### 18.1 视觉验收

- 页面中不存在毛玻璃、环境光斑或装饰性渐变。
- 不依赖蓝紫色表达 AI 属性。
- 主要页面在灰度模式下仍有明确层级。
- 单屏最多一个明显阴影面板。
- 同类组件的圆角、边界和间距一致。
- 长文本区域没有低对比度或透明背景。
- 不出现 Emoji 与线性图标混用。

### 18.2 首页验收

- 1366×768 下完整看到标题、上传入口和主按钮。
- 375×812 下主上传按钮位于首屏或轻微滚动范围内。
- 首次用户无需打开设置即可创建任务。
- 页面不出现 ASR、Prompt 等工程术语。

### 18.3 处理页验收

- 一眼可以识别当前步骤和总体进度。
- 不重复展示步骤信息。
- 实时内容拥有页面最大视觉权重。
- 用户向上滚动时不会被强制拉回底部。

### 18.4 内容库验收

- 桌面端列表具有稳定列结构。
- 删除操作默认不可见。
- 状态不会形成大量彩色块。
- 标题超长、文件名超长和错误状态下布局不破坏。

### 18.5 动效验收

- 不存在装饰性循环动画。
- 常规反馈不超过 220ms。
- Drawer 和 Modal 不超过 260ms。
- 动效只使用 opacity 和 transform，进度使用 scaleX。
- Reduced Motion 下全部功能正常。

### 18.6 工程验收

- TypeScript 构建无错误。
- ESLint 无新增错误和警告。
- 375、768、1024、1366、1440 宽度完成检查。
- 上传、SSE 进度、取消、重新生成、导出和删除流程均完成回归。
- Chrome、Edge 最新稳定版显示一致。

## 19. 最终效果定义

完成后的 Video2Knowledge 不应该让用户首先感叹“这个页面很 AI”，而应该让用户产生以下判断：

- 这是一个成熟产品。
- 设计者理解内容生产。
- 信息安排很清楚。
- 我愿意把自己的素材放进来。
- 我可以长时间使用它。
- 生成结果值得继续编辑和发布。

高级感最终来自准确，而不是装饰；来自内容被认真对待，而不是界面努力表现自己。
