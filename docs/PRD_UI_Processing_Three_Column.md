## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 产品模块 | 内容处理流程页 |
| 优先级 | P0 |
| 目标端 | Web，桌面端优先 |
| 需求类型 | 信息架构与交互体验优化 |

## 2. 背景与问题

当前处理页已能通过 SSE 展示整体进度、当前阶段进度以及转录、章节、知识、文章等阶段产物，但页面采用“左侧流程 + 主区域纵向堆叠”的结构。随着产物增多，用户需要上下滚动寻找最新结果，流程状态、实时产出和阶段进度混在同一视觉区域，存在以下问题：

1. 用户不能同时看见完整流程、当前产出和各阶段进度。
2. 新结果不断向页面下方追加，当前关注位置容易被打断。
3. 已完成结果缺少稳定入口，查看上一阶段需要滚动查找。
4. 左栏当前阶段依靠蓝色竖杠和小圆点表达，运行状态不够直观。
5. 已完成与待处理阶段的进度卡片缺少明显的“已经落定”差异。

## 3. 产品目标

### 3.1 核心目标

将处理页重构为稳定的三栏工作台，让用户在同一屏内完成三件事：

- 左栏快速定位当前处于哪个处理阶段。
- 中栏持续阅读当前阶段产出，并可翻页回看已有结果。
- 右栏判断每个阶段的完成度、状态和耗时。

### 3.2 用户价值

- 降低长任务等待过程中的不确定感。
- 让每一次阶段产出立即可见，而不是等全部完成后统一查看。
- 用户回看旧结果时不丢失对最新处理状态的感知。
- 形成“左侧导航—中间内容—右侧监控”的稳定操作心智。

### 3.3 成功指标

上线后两周观察：

| 指标 | 目标 |
|---|---|
| 处理中页面的阶段结果查看率 | 较当前提升 30% |
| 用户回看上一阶段结果的操作成功率 | ≥ 95% |
| 当前阶段识别正确率（可用性测试） | ≥ 90% |
| 因“页面无响应/不知道是否仍在运行”产生的主动终止率 | 较当前下降 20% |
| 三栏首屏在 1440px 宽度下的横向溢出 | 0 |

## 4. 范围说明

### 4.1 本期范围

- 仅优化上传任务进入处理状态后的页面。
- 保留现有 5 个处理阶段及其顺序。
- 保留整体进度、已耗时、终止任务能力。
- 新增中栏单卡片结果浏览与翻页交互。
- 新增右栏分阶段进度卡片。
- 补齐加载中、已完成、待处理、失败、中止和断线重连状态。

### 4.2 非本期范围

- 不调整 AI 处理流程和阶段顺序。
- 不修改处理完成后的资产详情页信息架构。
- 不新增人工编辑、阶段重跑或跳过阶段能力。
- 不将多个任务放在同一页面并行监控。
- 不重新设计上传页、资产列表页和导出流程。

## 5. 页面信息架构

### 5.1 桌面端整体结构

处理页由顶部任务状态条和下方三栏工作区组成。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 正在整理内容 · 文件名    ✓──✓──◌──○──○  48% · 02:31          [终止] │
├──────────────────┬────────────────────────────────┬──────────────────────────┤
│ 左：流程概览     │ 中：阶段产出                   │ 右：阶段进度             │
│ ① 音频提取  ✓   │ ┌────────────────────────────┐ │ [音频提取] 100% 已完成  │
│ ② 语音转录  ✓   │ │ 语音转录 · 已完成     2/5 │ │ [语音转录] 100% 已完成  │
│ ③ 章节划分  ◌   │ │                            │ │ [章节划分]  50% 处理中  │
│ ④ 知识提取  4   │ │ 当前/所选阶段结果，独立滚动 │ │ [知识提取]   0% 等待中  │
│ ⑤ 文章生成  5   │ │                            │ │ [文章生成]   0% 等待中  │
│                  │ ├────────────────────────────┤ │                          │
│                  │ │ [上一页]  2 / 5  [回到最新]│ │                          │
│                  │ └────────────────────────────┘ │                          │
└──────────────────┴────────────────────────────────┴──────────────────────────┘
```

### 5.2 栅格建议

| 区域 | 建议宽度 | 行为 |
|---|---:|---|
| 左栏 | 240–254px 固定 | 保留现有流程概览，不随中栏内容缩放 |
| 中栏 | `minmax(480px, 1fr)` | 主内容区，占据剩余空间 |
| 右栏 | 300–320px 固定 | 展示 5 张阶段进度卡片 |
| 栏间距 | 20–24px | 使用页面背景形成自然分区 |

工作区高度建议为视口高度减去全局导航和任务状态条；三栏分别独立滚动。中栏阶段结果卡固定占满工作区可用高度，不能因流式内容增长而推高整页。

## 6. 顶部任务状态条

顶部状态区作为三栏的共同上下文，不使用卡片容器，以单条紧凑时间线展示：

- 主标题：“正在整理内容”；完成后为“内容整理完成”；失败后为“处理未完成”。
- 文件名：单行省略，悬停显示完整名称。
- 总进度：5 个阶段节点组成的横向时间线，节点分别显示等待、转圈、完成和失败状态。
- 时间线右上角显示总百分比和已完成阶段数，如“2/5 完成 · 48%”。
- 已用时：`mm:ss`，超过 1 小时后显示 `hh:mm:ss`。
- “终止”按钮：沿用现有二次确认逻辑；任务结束后隐藏。

顶部区域仅使用底部分隔线，不使用圆角、阴影、独立背景或卡片边框。总进度沿用现有计算方式：`(已完成阶段 × 100 + 当前阶段百分比) ÷ 5`。总进度只允许向前增长，SSE 重连或乱序事件不得导致百分比回退。

## 7. 左栏：流程概览

### 7.1 保留内容

保留“处理流程”标题、5 个阶段名称、灰色阶段连接线和现有顺序：

1. 音频提取
2. 语音转录
3. 章节划分
4. 知识提取
5. 文章生成

### 7.2 状态视觉

| 状态 | 圆形标识 | 文案颜色 | 辅助信息 |
|---|---|---|---|
| 待处理 | 阶段序号 | 中性灰 | 不显示进度 |
| 处理中 | 蓝色圆形加载转圈 | 蓝色 | 显示一行当前动作，超出省略 |
| 已完成 | 绿色对勾 | 深灰/绿色辅助色 | 可显示“已完成”或阶段耗时 |
| 失败 | 红色叉号 | 红色 | 显示一行失败摘要 |
| 已中止 | 灰色停止图标 | 灰色 | 显示“已终止” |

### 7.3 视觉调整

- 删除当前激活项最左侧的蓝色竖杠，即移除现有 `border-left` 激活态。
- 保留贯穿阶段圆点的浅灰连接线；该线只表达流程顺序，不表达当前进度。
- 当前阶段改用 14–16px 的环形 spinner 持续旋转，旋转周期建议 0.8–1.0 秒。
- 可保留当前项的浅蓝背景，但不使用位移或缩放，避免侧栏抖动。
- 动效只作用于 spinner 的 `transform`；用户系统开启“减少动态效果”时，以静态蓝色圆环替代。

### 7.4 交互

- 处理中，已完成阶段可以点击；点击后中栏切换到对应阶段结果。
- 当前阶段可以点击并回到最新流式结果。
- 待处理阶段不可点击，鼠标样式为默认，不能出现误导性的 hover。
- 左栏点击与中栏翻页使用同一套 `viewingStage` 状态。

## 8. 中栏：固定阶段产出卡片

### 8.1 卡片结构

中栏始终只显示一个固定卡片，分为三部分：

1. 卡片头部：阶段名称、状态标签、阶段序号（如“3/5”）和“回到最新”入口。
2. 卡片内容区：当前选择阶段的结果，内部独立滚动。
3. 卡片底部：上一页、页码/阶段圆点、下一页。

卡片本身在阶段切换时不改变尺寸。头部和底部分页器固定，只有内容区滚动，避免流式输出造成布局跳动。

### 8.2 默认跟随规则

- 进入处理页后，默认开启“自动跟随最新阶段”。
- 收到 `step_start` 时，中栏自动切换至新阶段，并显示该阶段的实时产出。
- 用户主动查看已完成阶段后，暂停自动切换，防止阅读被新事件打断。
- 暂停跟随后，头部显示蓝色弱提示：“后台正在处理：{当前阶段}”，同时提供“回到最新”按钮。
- 用户点击“回到最新”或点击左栏当前阶段后，恢复自动跟随。
- 用户仅滚动当前内容不视为退出自动跟随。

### 8.3 翻页规则

- 每个处理阶段对应一页，共 5 页。
- “上一页”可切换到前一项已有产出；第一阶段时禁用。
- “下一页”只能进入已完成阶段或当前正在处理阶段，未来待处理阶段禁用。
- 点击页码圆点遵循相同权限；待处理页显示锁定/禁用态。
- 阶段切换后内容滚动位置回到顶部；再次返回某阶段时，本期不保留上次滚动位置。
- 键盘焦点在卡片内时支持 `Alt + ←/→` 翻页，并为按钮提供可读的 `aria-label`。

### 8.4 各阶段内容定义

| 阶段 | 处理中展示 | 完成后展示 | 空态/兜底 |
|---|---|---|---|
| 音频提取 | 当前动作日志，如“正在转换为 16kHz 单声道” | 音频文件信息、时长、格式；可选音频播放器 | “正在准备音频…” |
| 语音转录 | 已返回的转录文本持续追加；底部显示输入光标 | 完整转录文本、分段数 | 若暂不支持文本分片，展示模型请求进度与处理说明 |
| 章节划分 | 分析说明或已生成的章节逐项出现 | 章节标题、起止时间列表 | “正在分析内容结构…” |
| 知识提取 | 已返回的知识项按分类追加 | 概念、框架、方法、工具、论文、代码示例、洞察 | “正在提炼知识…” |
| 文章生成 | Markdown 内容逐段追加并实时渲染 | 完整文章预览 | “正在生成文章结构…” |

### 8.5 流式显示规则

- 文本增量采用追加方式，不对整个卡片做淡入动画。
- 新内容默认自动滚动到内容区底部；用户向上滚动超过 80px 后暂停自动滚动。
- 暂停自动滚动时显示悬浮按钮“查看最新内容”；点击后滚动到底部并恢复跟随。
- 单次刷新合并同一动画帧内的增量，避免高频 SSE 导致卡顿。
- Markdown 流式阶段允许未闭合语法以纯文本或容错方式显示，完成后再进行一次完整渲染。
- 阶段完成后保留最终快照，后续翻页不依赖仍然打开的 SSE 连接。

### 8.6 阶段切换反馈

- 切换时仅内容区使用 120–160ms 的轻微淡入；卡片外框不动。
- 新阶段首次出现时，状态标签从“等待中”变为“处理中”。
- 阶段完成时显示对勾与“已完成”，停止输入光标和流式动效。
- 失败时保留已经产生的部分结果，在卡片顶部展示错误提示，不清空内容。

## 9. 右栏：阶段进度卡片

### 9.1 卡片内容

右栏宽度控制在 224–246px，按处理顺序固定展示 5 张紧凑卡片。卡片包含：

- 阶段序号与名称。
- 状态文案：等待中、处理中、已完成、失败、已终止。
- 处理中、等待中和失败状态显示当前百分比。
- 语音转录处理中有 API 分片信息时，可补充显示“请求 3/8”。
- 已完成卡片只保留阶段名称、对勾和“已完成”，隐藏百分比及其他信息。

所有右栏卡片不显示底部说明文字和阶段级进度条，避免与顶部总时间线重复表达进度。

### 9.2 状态视觉规范

| 状态 | 卡片表现 | 进度条 | 动效 |
|---|---|---|---|
| 待处理 | 浅灰背景、低对比边框，显示 0% | 无 |
| 处理中 | 白底、蓝色描边或柔和蓝色外发光，显示百分比 | 卡片玻璃光扫 |
| 已完成 | 稳定白底、实线中性边框、轻微内阴影；只显示对勾和“已完成” | 无 |
| 失败 | 淡红背景、红色描边，保留失败前百分比 | 无 |
| 已终止 | 灰色背景，保留终止前百分比 | 无 |

“已完成阶段卡片给人已经固定的效果”定义为：视觉位置不再变化、卡片高度收缩、边框由动态强调转为稳定实线、内部进度固定为 100% 但不再显示数值，取消所有流光与呼吸动效，并增加对勾/“已完成”戳记。不要使用真实图钉作为唯一表达，以免用户误解为手动置顶功能。

### 9.3 行为规则

- 卡片顺序始终固定，不因完成或失败重新排序。
- 点击已完成或当前阶段卡片，中栏切换到相应结果。
- 待处理卡片不可点击。
- 新 SSE 数据只更新对应卡片，其他已完成卡片不可闪动或重新进入加载态。
- 百分比事件乱序时取 `max(现有值, 新值)`；收到 `step_result` 后固定为 100%。

## 10. 状态与异常处理

### 10.1 页面状态模型

| 事件 | 左栏 | 中栏 | 右栏 |
|---|---|---|---|
| `step_start` | 对应阶段开始转圈 | 自动跟随开启时切到该阶段 | 卡片变为处理中 |
| `step_progress` | 更新辅助文案 | 追加/替换当前产出 | 更新百分比与摘要 |
| `step_result` | 变为完成对勾 | 固化最终结果，开放翻页 | 固定为 100% 已完成 |
| `step_error` | 显示红色叉号 | 保留部分结果并展示错误 | 显示失败及失败前进度 |
| `complete` | 全部完成 | 停止流式状态，停在文章页 | 全部已完成卡片固定 |
| `cancelled` | 当前及后续显示中止/待处理 | 保留已有结果 | 当前阶段显示已终止 |

### 10.2 SSE 断线

- 首次断线在顶部显示“连接中断，正在重连…”，不立即把阶段标记为失败。
- 自动重连期间保留全部进度和产出，不清屏、不回退。
- 重连成功后提示 2 秒并消失。
- 达到既定重试上限后显示“暂时无法获取实时进度”，提供“重新连接”按钮。
- 若服务端任务仍在执行，重新连接后应以持久化阶段结果和最新状态补齐 UI。

### 10.3 数据为空或解析失败

- 已完成阶段没有可展示结果时，显示“该阶段已完成，暂无可预览内容”，不得保持骨架屏。
- 单个阶段结果解析失败只影响该阶段卡片，其他阶段仍可浏览。
- 未知事件字段忽略处理并记录前端日志，不阻塞主流程。

## 11. 响应式方案

### 11.1 ≥ 1280px

完整三栏常驻展示，左 254px、中间自适应、右 320px。

### 11.2 1024–1279px

仍保留三栏，左栏收窄至 210px，右栏收窄至 280px；阶段辅助文案可隐藏，中栏最小宽度 420px。

### 11.3 < 1024px

三栏改为顶部标签切换：“流程 / 产出 / 进度”，默认进入“产出”。顶部状态条常驻；当前阶段变化通过标签上的蓝点和状态提示表达。该模式下不强行横向滚动三栏。

### 11.4 < 640px

任务状态条改为两行；终止按钮置于第二行右侧。中栏卡片铺满宽度，分页按钮保证至少 44×44px 点击区域。

## 12. 视觉与可用性规范

- 延续现有中性灰背景、蓝色主状态、绿色完成、红色失败的色彩体系。
- 状态不可只依赖颜色，必须同时提供图标和文字。
- 正文与背景对比度满足 WCAG AA；正文不低于 14px。
- 所有进度条提供 `role="progressbar"`、当前值和阶段名称。
- 状态变化通过 `aria-live="polite"` 播报，流式正文增量不逐字播报，避免读屏刷屏。
- spinner、进度流光和淡入均遵循 `prefers-reduced-motion`。
- 中栏正文选择和复制时，新内容到达不得抢夺焦点或清除选区。

## 13. 数据与技术需求

### 13.1 前端状态建议

新增或明确以下状态：

| 状态 | 类型 | 用途 |
|---|---|---|
| `activeStage` | 阶段 key | 后端当前正在执行的阶段 |
| `viewingStage` | 阶段 key | 中栏当前查看的阶段 |
| `followLatest` | boolean | 是否自动跟随当前阶段 |
| `stageOutputs` | `Record<stage, output>` | 每阶段可回看的结果快照 |
| `stageProgress` | `Record<stage, progress>` | 右栏独立进度数据 |
| `autoScroll` | boolean | 当前结果是否跟随到底部 |

`activeStage` 与 `viewingStage` 必须分离，这是实现“后台继续处理、用户翻页回看”的前提。

### 13.2 SSE 能力差距

现有接口已提供 `step_start`、`step_progress`、`step_result`、`step_error` 和 `complete`，其中文章生成通过 `step_progress.detail` 传输文本增量；转录、章节和知识目前主要在 `step_result` 时一次性返回最终结果。若产品要求所有阶段均“流式展示产出”，后端需新增统一事件或扩展现有事件。

建议新增：

```json
{
  "event": "stage_output",
  "data": {
    "step": "transcribe",
    "mode": "append",
    "content_type": "text",
    "payload": "新增文本片段",
    "sequence": 12
  }
}
```

- `mode`：`append` 或 `replace`。
- `content_type`：`text`、`chapters`、`knowledge`、`markdown`、`log`。
- `sequence`：阶段内单调递增，用于去重和乱序保护。
- 暂不改后端时，第一版可用 `step_progress.detail` 流式展示处理说明，在 `step_result` 后替换为完整产物；文章仍保持真实内容流式输出。

### 13.3 阶段耗时

右栏若要展示阶段耗时，需要前端记录每个 `step_start` 与 `step_result/step_error` 的本地时间，或由服务端在事件中返回 `started_at`、`finished_at`、`duration_ms`。服务端时间为最终可信来源。

### 13.4 性能要求

- 流式事件 UI 合并刷新频率建议不高于 10 次/秒。
- 单阶段长文本只保留一份主数据，避免重复复制 Markdown 字符串。
- 结果内容超过 5,000 行时考虑列表虚拟化；本期至少保证 100,000 字文本滚动无明显阻塞。
- 三栏切换不得重新请求已有结果，除非本地不存在最终快照。

## 18. 动态视觉决策与实现状态

### 18.1 动效主语言

本界面统一采用“玻璃光扫”风格：以品牌蓝渐变边缘、低透明度光扫、轻微卡片抬升和内容淡入构成动态反馈。主内容卡只做极轻的平移与缩放，右侧处理中进度卡允许小角度 3D 倾斜；已完成卡片停止全部循环动效，形成“处理中有生命力、完成后稳定沉淀”的节奏。

实现约束：

- 光扫、悬浮、spinner、输入光标均只动画 `transform` 与 `opacity`。
- 阶段进度条通过 `scaleX()` 更新，不动画宽度。
- 光效层统一 `pointer-events: none`，不遮挡按钮与正文选择。
- 动画元素使用 `backface-visibility: hidden`，交互卡片使用 `will-change: transform`。
- 移动端禁用 3D 倾斜与主卡 hover 光扫。
- `prefers-reduced-motion` 下关闭持续旋转、光扫和位移动画。
